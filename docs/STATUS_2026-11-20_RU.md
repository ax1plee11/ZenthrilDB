## Новая проверка Ubuntu 24.04

Docker Desktop Linux engine запущен для этого прогона. Использован имеющийся образ `zenthrildb-ci-ubuntu:local`, фактически Ubuntu 24.04.5 LTS x86_64, GCC 13.3.0 и CMake 3.28.3. Исходники подключались в контейнеры по `/src` только для чтения. Два независимых чистых каталога сборки находились в `/tmp/build-Debug` и `/tmp/build-Release`.

| Конфигурация | Сборка | CTest | Установленный CLI |
| --- | --- | --- | --- |
| Debug | Успех | 5/5 за 109,99 с | Успех |
| Release | Успех | 5/5 за 31,35 с | Успех |

В Debug прошли 15 аварийных публикаций и 23 сценария I/O для каждого режима v1/v2, а также шесть прерываний физического recovery v2. Дополнительно выполнялись прежние проверки WAL, checkpoint, страниц, блокировок и hardening. В подробных журналах строк SKIP не найдено. Release проходит общий набор без инъекций отказов.

Проверка установленного CLI выполнена в отдельных контейнерах с тестовыми файлами на их Linux-файловой системе. Проверены запись и чтение, checkpoint, снимок v2, независимый baseline без рабочей пары, отказ при утрате обязательных файлов с неполным хвостом WAL, сохранность четырёх файлов backup и наследование v2 дочерним снимком. Исторические кадры WAL сравнивались побайтно после преамбулы. SHA-256 исходной пары и backup совпали.

Контрольные суммы 123 файлов исходников до завершения и после проверки совпали. Реальные пользовательские базы в испытаниях не использовались.

### Команды и журналы

Из корня репозитория внутри контейнера для Debug выполнялись следующие команды. Для Release использовались каталог `/tmp/build-Release` и `-DCMAKE_BUILD_TYPE=Release`.

```sh
cmake -S /src -B /tmp/build-Debug -DCMAKE_BUILD_TYPE=Debug -DZENTHRILDB_BUILD_TESTS=ON
cmake --build /tmp/build-Debug --parallel 3
ctest --test-dir /tmp/build-Debug --output-on-failure --no-tests=error --timeout 240
cmake --install /tmp/build-Debug --prefix /logs/install-Debug
bash -eu -o pipefail /logs/cli-v2-smoke.sh
```

Результаты сохранены в `build-21/linux-v2-20261120/` — `Debug-ctest.log`, `Release-ctest.log`, подробные `*-details.log`, логи сборки, установки и CLI, скрипт `cli-v2-smoke.sh`, manifest `source-sha256.json`. Установленные бинарники находятся в `install-Debug/bin/` и `install-Release/bin/`. Тестовые контейнеры удалены штатным `--rm`.

## Граница результата и дальнейший шаг

Закрыт актуальный Linux-прогон текущего этапа надёжности. Проверка выполнена в контейнерах Docker Desktop с Linux-файловой системой. Аппаратное отключение питания, сетевые файловые системы, отказы контроллера и злонамеренная перепись согласованного комплекта находятся за пределами результата.

Следующий шаг дорожной карты — отдельно проверяемое построение кандидата журнала из допустимого суффикса с сопоставлением полному replay. Перед применением сокращения потребуются формат границы, монотонность LSN и Transaction ID, REDO/UNDO, повторный crash recovery и безопасная публикация. Исходная история WAL сохраняется до отдельной приёмки.
