# Физическое восстановление страниц

При открытии связанной пары FileManager проверяет заголовок базы и страницу идентичности. LogManager сверяет UUID, поколение и границу LSN. RecoveryCoordinator вычисляет итоговое состояние по полным образам WAL и исходам транзакций. Он проверяет историю роста файла, типы и номера слотов, CRC и LSN образов. CRC неисправной страницы не подтверждается, поэтому её поля не участвуют в выборе образа.

| Состояние | Действие |
|---|---|
| CRC страницы неверен, слот однозначно восстановим | Запись полного итогового образа из WAL или проверенного baseline и синхронизация. |
| Последний физический слот неполон или отсутствует | Восстановление полного образа, если история подтверждает размер и все добавляемые слоты. |
| Незавершённая мутация | Использование согласованного before-image. Хвост незавершённого расширения удаляется только в пределах, объяснённых WAL. |
| Нет образа, история противоречива или файл не принадлежит паре | Отказ во время планирования. База и WAL остаются неизменными, включая неполный хвост журнала. |
| CRC корректен, а версия, тип, физический номер или LSN недопустимы | Диагностический отказ. |

План строится до каких-либо изменений. Исправление хвоста WAL разрешается после проверки всех нужных слотов. При росте сначала устанавливается итоговый заголовок из WAL, затем последовательно записываются итоговые страницы. Подтверждённое планом сокращение хвоста выполняется после записи страниц. Повреждение заголовка файла, страницы 0, префикса либо полного кадра WAL требует отдельного восстановления из проверенной копии. Режим совместимости старого формата сохраняет прежнее поведение.

Поколение связывает весь WAL с базой через его префикс и страницу 0. Формат страниц не содержит собственного идентификатора поколения. Криптографическая аутентификация и обнаружение отката всей пары относятся к отдельным задачам. Модель текущих испытаний покрывает управляемые I/O-сбои и прерывание процесса, включая момент после синхронизации ремонтной записи.

`ctest -L security` запускает сценарии ремонта, отказа с побайтовой проверкой и повторного открытия. Debug включает отдельный процесс, который прекращает работу после записи и синхронизации восстановленной страницы. При отсутствии baseline образы страниц берутся из полной истории WAL. При наличии проверенного baseline физический план использует его состояние и WAL после границы, а сохранённый исторический префикс проходит валидацию. Условия сокращения журнала определены отдельно в [дорожной карте](roadmap/STORAGE_RECOVERY_NEXT_RU.md).

## Прерывание восстановления v2

20 ноября 2026 года `tests/test_physical_recovery_crash.cpp` расширен тремя сценариями для поколения с обязательным baseline.

| Сценарий | Ожидаемое состояние первой повреждённой страницы |
| --- | --- |
| Baseline без последующих изменений | Полный образ из базового снимка |
| REDO после подтверждённой записи в WAL без записи новой страницы | Подтверждённый after-image |
| UNDO после записи неподтверждённой страницы | Согласованный before-image |

Для каждого сценария повреждаются CRC двух страниц. Первый дочерний процесс завершается через `_Exit(91)` после синхронизации ремонта первой страницы. Тест подтверждает, что первая страница восстановлена, а вторая ещё повреждена. Второй дочерний процесс прерывается после ремонта второй страницы. В обоих случаях ожидаемый код завершения обязателен.

Затем два штатных открытия проверяют подтверждённое значение, вторую запись и согласованность. Файл базы сравнивается побайтно с ожидаемым состоянием. WAL, baseline, manifest и исходная пара также сохраняют ожидаемые байты. Проверка `verifySnapshot` подтверждает обязательный маркер v2.

Windows x64 Debug прошёл 5/5 групп CTest за 257,79 с, включая шесть новых процессных прерываний. Группа Security прошла за 18,54 с. Windows Release прошёл 5/5 за 111,92 с. Новые аварийные сценарии включаются только в Debug. Логи находятся в `build-21-win/v2-recovery-*-ctest.log`.

Текущий код также прошёл чистые сборки и 5/5 групп CTest в Ubuntu 24.04.5 LTS, Debug и Release. Debug выполнил новые прерывания recovery v2. [Команды и результаты](STATUS_2026-11-20_RU.md#новая-проверка-ubuntu-2404). Прерывание процесса на указанных границах не подтверждает поведение носителя при физическом отключении питания.
