# Физическое восстановление страниц

При открытии связанной пары FileManager проверяет заголовок базы и страницу идентичности. LogManager сверяет UUID, поколение и границу LSN. RecoveryCoordinator вычисляет итоговое состояние по полным образам WAL и исходам транзакций. Он проверяет историю роста файла, типы и номера слотов, CRC и LSN образов. CRC неисправной страницы не подтверждается, поэтому её поля не участвуют в выборе образа.

| Состояние | Действие |
|---|---|
| CRC страницы неверен, слот однозначно восстановим | Запись полного итогового образа из WAL и синхронизация. |
| Последний физический слот неполон или отсутствует | Восстановление полного образа, если история подтверждает размер и все добавляемые слоты. |
| Незавершённая мутация | Использование согласованного before-image. Хвост незавершённого расширения удаляется только в пределах, объяснённых WAL. |
| Нет образа, история противоречива или файл не принадлежит паре | Отказ во время планирования. База и WAL остаются неизменными, включая неполный хвост журнала. |
| CRC корректен, а версия, тип, физический номер или LSN недопустимы | Диагностический отказ. |

План строится до каких-либо изменений. Исправление хвоста WAL разрешается после проверки всех нужных слотов. При росте сначала устанавливается итоговый заголовок из WAL, затем последовательно записываются итоговые страницы. Подтверждённое планом сокращение хвоста выполняется после записи страниц. Повреждение заголовка файла, страницы 0, префикса либо полного кадра WAL требует отдельного восстановления из проверенной копии. Режим совместимости старого формата сохраняет прежнее поведение.

Поколение связывает весь WAL с базой через его префикс и страницу 0. Формат страниц не содержит собственного идентификатора поколения. Криптографическая аутентификация и обнаружение отката всей пары относятся к отдельным задачам. Модель текущих испытаний покрывает управляемые I/O-сбои и прерывание процесса, включая момент после синхронизации ремонтной записи.

`ctest -L security` запускает сценарии ремонта, отказа с побайтовой проверкой и повторного открытия. Debug включает отдельный процесс, который прекращает работу после записи и синхронизации восстановленной страницы. Старые образы WAL нужны для ремонта. Условия сокращения журнала будут определены отдельно при приёмке [безопасного checkpoint](roadmap/STORAGE_RECOVERY_NEXT_RU.md#безопасный-checkpoint).
